<objective>
Close SEC-09: percent-encode JMAP blob download URL template substitutions so a filename (or blob id) containing spaces, Unicode, or URL-reserved characters produces a valid URL instead of being rejected by the server or silently mangled.

Purpose: `JmapClient::download_blob()` at src/jmap/mod.rs:864-894 does raw `.replace("{name}", "attachment")` on the `downloadUrl` template. Currently safe because "attachment" is hardcoded, but per D-07 this will be changed to user-intended filenames, AND the `{blobId}` substitution already uses the server-supplied blob id which can contain characters invalid in a URL path segment. Per D-05 and D-06, add the `percent-encoding` crate and apply `NON_ALPHANUMERIC` to both `{blobId}` and `{name}`.

Output: `download_blob()` produces well-formed URLs for any filename/blobId input; unit tests prove encoding behavior.
</objective>
