    Per D-04, D-05, D-06:

    1. Add a private helper `fn build_uid_report_body(uid: &amp;str) -> String` that returns an RFC 4791 `calendar-query` REPORT body:
       ```xml
       &lt;?xml version="1.0" encoding="utf-8" ?&gt;
       &lt;C:calendar-query xmlns:D="DAV:" xmlns:C="urn:ietf:params:xml:ns:caldav"&gt;
         &lt;D:prop&gt;
           &lt;D:getetag/&gt;
           &lt;C:calendar-data/&gt;
         &lt;/D:prop&gt;
         &lt;C:filter&gt;
           &lt;C:comp-filter name="VCALENDAR"&gt;
             &lt;C:comp-filter name="VEVENT"&gt;
               &lt;C:prop-filter name="UID"&gt;
                 &lt;C:text-match collation="i;unicode-casemap" match-type="equals"&gt;{escaped_uid}&lt;/C:text-match&gt;
               &lt;/C:prop-filter&gt;
             &lt;/C:comp-filter&gt;
           &lt;/C:comp-filter&gt;
         &lt;/C:filter&gt;
       &lt;/C:calendar-query&gt;
       ```
       Escape XML special chars in `uid` before inserting: `&amp; &lt; &gt; " '` → entities. Inline escape function, do NOT add a new crate dep.

    2. Rewrite `get_event_by_id`:
       - Fetch `list_calendars()`.
       - For each calendar, spawn a future issuing a REPORT (method="REPORT", Depth: 1, Content-Type: application/xml) with `build_uid_report_body(uid)` to `calendar.href`.
       - `join_all` the futures.
       - For each response:
         - HTTP 200/207 with &gt;= 1 matching VEVENT → parse the first match and return `Ok(Some(event))`.
         - HTTP 400 or 501 → record as "fallback needed", continue other calendars.
         - Other errors → log via `tracing::warn!` and continue.
       - If NO calendar returned a match AND at least one returned 400/501, fall back to the existing full-fetch pattern (call the old logic — keep it as `get_event_by_id_full_fetch` private helper). Log via `tracing::warn!(uid, "UID REPORT unsupported, falling back to full fetch")` per D-05.
       - If no match and no 400/501: return `Ok(None)`.

    3. Add unit tests for `build_uid_report_body` verifying presence of the collation/match-type attributes and UID escaping. Parsing tests only if the existing REPORT parser is directly callable with a canned XML string.

    Avoid: removing the existing full-fetch code path (needed as fallback), issuing REPORTs sequentially, using prefix/substring match-type.

    Reference: Phase 15 CONTEXT.md D-04, D-05, D-06.
