# Requirements: Calendar Access and Management

**Defined:** 2026-04-03
**Core Value:** Users can manage Fastmail data without leaving the terminal or AI assistant, with automation-friendly APIs that stay faithful to Fastmail's actual protocol boundaries

## v1 Requirements

### Calendar Collections

- [x] **CAL-01**: User can list all calendars available in their Fastmail account
- [x] **CAL-02**: User can create a new calendar with a display name
- [x] **CAL-03**: User can rename or update basic metadata on an existing calendar
- [x] **CAL-04**: User can delete an existing calendar

### Event Discovery

- [x] **EVT-01**: User can list future events for the rest of the current day without supplying a date range
- [x] **EVT-02**: User can list events for the current week using a convenience flag
- [x] **EVT-03**: User can list events for an explicit start/end range
- [x] **EVT-04**: User can filter event listings to a specific calendar
- [x] **EVT-05**: User can fetch a single event with full stored details

### Event CRUD

- [x] **EVT-06**: User can create a one-off event with title, start, end, and timezone
- [x] **EVT-07**: User can set or update an event's location and description
- [x] **EVT-08**: User can add, update, and remove attendees on an event
- [x] **EVT-09**: User can add, update, and remove recurrence on an event
- [x] **EVT-10**: User can add, update, and remove reminders on an event
- [x] **EVT-11**: User can update an existing event safely without overwriting concurrent server changes
- [x] **EVT-12**: User can delete an event

### CLI Experience

- [x] **CLI-01**: User can manage calendars and events from dedicated CLI subcommands without hand-writing CalDAV requests
- [x] **CLI-02**: User can use both shortcut range flags (`--today`, `--week`) and explicit `--start` / `--end` filters for event listing
- [x] **CLI-03**: CLI JSON output for calendars and events includes identifiers needed for follow-up CRUD actions

### MCP GraphQL

- [x] **MCP-01**: AI agents can list calendars through MCP GraphQL
- [x] **MCP-02**: AI agents can list events through MCP GraphQL using default and explicit date ranges
- [x] **MCP-03**: AI agents can fetch a full event through MCP GraphQL
- [x] **MCP-04**: AI agents can create and update calendars through MCP GraphQL
- [x] **MCP-05**: AI agents can create and update events through MCP GraphQL
- [x] **MCP-06**: AI agents can delete calendars and events through MCP GraphQL with explicit confirmation semantics

### Validation

- [x] **VAL-01**: Calendar collection CRUD is validated against a live Fastmail account
- [x] **VAL-02**: Event list/get/create/update/delete flows are validated against a live Fastmail account
- [x] **VAL-03**: Live validation confirms attendee, recurrence, and reminder fields round-trip without unexpected data loss

## v2 Requirements

### Calendar Intelligence

- **INT-01**: User can query free/busy availability across a time range
- **INT-02**: User can ask the system to suggest meeting times

### Calendar Extensions

- **EXT-01**: User can subscribe to remote ICS / CalDAV calendars
- **EXT-02**: User can manage calendar sharing / ACL permissions
- **EXT-03**: MCP exposes a high-level "create event from text/email" helper

## Out of Scope

| Feature | Reason |
|---------|--------|
| JMAP calendar implementation | Fastmail publicly exposes calendars via CalDAV today |
| Built-in natural-language parsing in MCP calendar tools | Keep the API explicit and testable; agents can interpret email/prompt content externally |
| Calendar sharing / ACL administration | Larger scope than the requested CRUD baseline |
| Free/busy planning assistant flows | Useful follow-on, but not required to ship calendar CRUD |
| ICS feed subscription management | Adjacent import/sync feature, not part of the requested milestone |
