# Plan 10-01: Explicit Range Contract Closure

## Goal

Close the explicit event-range contract gap by making the shared listing helper reject partial explicit ranges, then align the CLI and MCP surface text to that rule so all three layers behave predictably.

## Contract Decision

- Partial explicit ranges are rejected, not honored.
- Supported modes remain narrow:
  - no `start`, no `end`, `week = false` => `default_today_range()`
  - `week = true` => `current_week_range()`
  - both `start` and `end` present => explicit parsed range
  - exactly one of `start` or `end` present => validation error stating both bounds are required
- Do not expand this phase into open-ended start-only or end-only filtering.
